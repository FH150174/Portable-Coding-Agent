## 固定版接口及配置证据

- CLI/Web 官方文档：https://opencode.ai/docs/cli/ 和 https://opencode.ai/docs/web/ 。TUI 为 opencode [project]；Web 为 opencode web --hostname 127.0.0.1 --port 4096。Web 命令本身会打开浏览器。绑定 127.0.0.1 限制网络监听范围。
- 配置、变量、自动升级和分享：https://opencode.ai/docs/config/ 。OPENCODE_CONFIG 指定配置文件，OPENCODE_CONFIG_CONTENT 的优先级高于项目配置；autoupdate:false 禁止升级，share:"disabled" 禁止会话分享；环境变量替换为 {env:DEEPSEEK_API_KEY}。
- 权限：https://opencode.ai/docs/permissions/ 。`permission` 可把动作设为 `allow`、`ask` 或 `deny`；多个 Shell 模式命中时以后匹配的规则为准。规则仅控制 OpenCode 的工具调用，不提供操作系统级隔离。启动器在进入选定工作区前扫描 Workspace、全局配置及祖先目录中的 OpenCode 配置/插件并拒绝风险项；Web 内之后切换目录仍不能保证受此扫描限制。
- DeepSeek 官方 OpenCode 接入：https://api-docs.deepseek.com/quick_start/agent_integrations/opencode/ 。官方建议 OpenCode >= v1.18.30。
- DeepSeek 当前模型：https://api-docs.deepseek.com/quick_start/pricing/ 。API 模型 ID 是 deepseek-flash；旧 deepseek-v4-flash 是兼容别名，不选作默认值。OpenCode 的 provider/model ID 为 deepseek/deepseek-flash。
- DeepSeek 模型列表和错误码：https://api-docs.deepseek.com/api/list-models/ 、https://api-docs.deepseek.com/quick_start/error_codes/ 。GET /models 可作认证预检；401 表示认证失败，402 余额不足，429 限流。
- 固定版数据路径源码：https://github.com/anomalyco/opencode/blob/v1.18.32/packages/core/src/global.ts 。XDG_DATA_HOME、XDG_CONFIG_HOME、XDG_CACHE_HOME、XDG_STATE_HOME 影响相应目录，TMP/TEMP 影响 Windows 临时目录。
- 固定版模型目录及打包：https://github.com/anomalyco/opencode/blob/v1.18.32/packages/core/src/models-dev.ts 、https://github.com/anomalyco/opencode/blob/v1.18.32/packages/opencode/script/build.ts 。二进制内含模型目录快照；OPENCODE_DISABLE_MODELS_FETCH 可避免在学校访问国际模型目录。
- 固定版 provider：https://github.com/anomalyco/opencode/blob/v1.18.32/packages/opencode/src/provider/provider.ts 、https://github.com/anomalyco/models.dev/blob/dev/providers/deepseek/provider.toml 。DeepSeek 在固定配置中钉住已打包的 @ai-sdk/openai-compatible 与 https://api.deepseek.com；该路径不需要首启从 npm 下载 provider 包。配置禁用外部插件、LSP/格式化器及自动下载。

## 审批档位设计（2026-09-29 补充）

`设置审批档位.cmd` 提供三个选择：只读（readonly：`edit` 和 `bash` 拒绝，工作区外目录拒绝）、逐项审批（manual：`edit` 和 `bash` 请求确认，工作区外目录请求确认）和工作区自动编辑（workspace：`edit` 自动通过，`bash` 与工作区外目录仍请求确认）。未选择时使用逐项审批。选择保存在 U 盘，新的 Web 或 TUI 进程启动时读取；更改档位前须停止 Web 服务，运行中的 TUI 应退出后重新打开。Web 服务记录与启动时档位关联，避免复用另一档位的旧进程。

固定版配置加载顺序见 https://github.com/anomalyco/opencode/blob/v1.18.32/packages/opencode/src/config/config.ts ：启动器逐一核对三份完整配置的 SHA-256，并将所选档位的完整配置文本通过 `OPENCODE_CONFIG_CONTENT` 传给子进程；`OPENCODE_CONFIG` 指向一个不存在的随机路径，避免校验后再次从磁盘读取基础配置。之后的机器托管配置仍可收紧策略。`OPENCODE_PERMISSION` 在托管配置之后合并，故启动器从子进程环境中移除继承的该变量，避免外部环境覆盖所选档位。U 盘上的选择文件只记录所选档位。

本版不提供 Shell 全自动批准档位。即使 `bash` 对某个命令设为 `ask`，用户批准后，该命令及其运行的项目代码仍可读取子进程环境中的 Key、访问其他可读文件；用文本模式拒绝某个命令也不能覆盖所有等价写法。TUI 的内置自动审批开关会自动批准部分本应请求确认的动作；验证启动器档位时应保持其关闭。这些档位是工作流设置，不是沙箱边界。

## 本机验证记录

验证机：当前 Windows x64 开发环境；未提供学校机房系统版本、策略或真实 DeepSeek Key。使用假 Key 和隔离目录，没有发起计费模型调用。

1. SHA-256：官方 ZIP 与 Releases API digest 一致；EXE 值如上。
2. EXE：--version 输出 1.18.32，退出码 0。
3. 配置/模型：设置隔离 XDG 目录、OPENCODE_CONFIG、假 Key、OPENCODE_DISABLE_MODELS_FETCH=true 后执行 models deepseek；返回 deepseek/deepseek-flash、deepseek/deepseek-v4-flash、deepseek/deepseek-v4-flash-vision-exp、deepseek/deepseek-v4-pro，退出码 0。采用第一个当前名称。
4. 路径：在隔离目录执行 debug paths，data/cache/config/state/tmp 全位于指定的项目测试目录下；bin/log/repos 也在上述目录内。home 仍显示当前 Windows 用户目录，不能据此宣称完全无本机痕迹。
5. 隔离副本用假 Key 与本机假 /models 服务通过预检，原生 Web 成功启动 OpenCode v1.18.32，仅监听 127.0.0.1:4096；再次启动复用同一 PID，退出入口停止该 PID 并清除运行状态。测试期间一份 OpenCode 日志未出现假 Key。目标机 Web/TUI、真实 API 及权限审批仍需机房环境复核；详情见验收手册。

## 已知边界

- 未取得用户真实 Key，因此无法验证实际 DeepSeek 推理、费用、余额与账户模型权限。假服务只能检验预检分类和错误展示。
- 浏览器缓存、Windows 事件、杀毒软件、最近文件、页面文件、进程内存，以及项目构建工具自己的缓存可能留在学校电脑。即使 XDG 路径受控，也不能保证零痕迹。
- 会话数据库在 U 盘时，异常拔盘可能损坏未提交的写入。应使用退出入口，确认进程停止后安全弹出；异常时先备份整个 Data 再修复。
- PowerShell 执行策略、学校应用限制、端口占用、代理/TLS 和 USB 写权限都需目标机实测；启动器不得绕过限制。
- 获批准的 Shell 命令可能间接读取/更改项目外文件及进程环境中的 Key；OpenCode 权限规则只能辅助审批，不能当作安全沙箱。工作区自动编辑档只自动批准文件编辑，命令仍请求确认。
- 如果课程项目缺少编译器或构建工具，代码仍可阅读和编辑，相应构建/测试则无法完成。可在自己的电脑将经许可的便携工具放入 Runtime，并自行验证架构、许可、PATH 和缓存位置；不要在机房首次运行时在线安装。


## 原生启动器与跨路径会话验证

Microsoft 的 .NET Framework 安装与系统要求文档：https://learn.microsoft.com/en-us/dotnet/framework/install/ 、https://learn.microsoft.com/en-us/dotnet/framework/get-started/system-requirements 。目标电脑需有 CLR 4/.NET Framework 4.x；本机编译成功不能证明所有学校电脑满足条件。

开发机的 Windows PowerShell 执行策略为 Restricted；日常 CMD 入口因此调用 C#/.NET Framework 原生 Launcher/PortableAgent.exe，无需在目标电脑更改执行策略。构建辅助脚本只用于允许脚本的个人开发电脑。原生启动器在执行前核对 OpenCode EXE 与固定配置的 SHA-256、目录联接点、写入空间和 DeepSeek /models 预检；运行时 Key 只传入子进程环境。配置 SHA-256 为 57b2b36833676af90add9ca2875196177f4da38d336570825862374b12265472。编译环境使用 Windows 自带 .NET Framework 4.x C# 编译器，发布包直接包含编好的 EXE。

隔离测试用假 Key 和 opencode serve 在 127.0.0.1 创建会话。把包含 Data 和 Workspace 的测试目录复制到另一绝对路径、暂时移除旧 Workspace 后，旧会话仍可列出，但 session.directory 留在旧路径；此风险与 OpenCode 上游问题 https://github.com/anomalyco/opencode/issues/33909 一致。原生启动器通过 Windows 的 winsqlite3.dll 先执行 SQLite 在线备份，再在一个事务中仅重写 USB Workspace 前缀下的 session.directory、session.path、project.worktree、project_directory.directory 和 workspace.directory。修复后用同一固定版 OpenCode 的 /session 与 /session/:id 端点确认原 ID 可列出且指向真实存在的新 Workspace；备份仍保存旧路径。迁移失败时停止启动并保留原数据，错误类型及 SQLite/文件错误码写入 U 盘日志。

迁移范围限定在数据库的项目路径元数据。测试库的历史 event.data JSON 仍有旧路径；Git 快照文件、历史工具输出及外部项目不自动重写。不能据此宣称所有历史引用都已迁移。目标学校电脑、真实 DeepSeek 对话续聊和浏览器状态仍需 F07 实机验收。Windows winsqlite3.dll 是跨路径迁移的依赖；若学校电脑缺少，启动器报 PCA130 并保留数据库，需要在个人电脑修复。

## 工作区安全边界

固定版 OpenCode 会查找项目 opencode.json/jsonc 和 .opencode 目录，并可加载外部 JS/TS 插件；源码见 https://github.com/anomalyco/opencode/blob/v1.18.32/packages/core/src/config.ts 和 https://github.com/anomalyco/opencode/blob/v1.18.32/packages/core/src/config/plugin/external.ts 。启动器拒绝整个 Workspace 中的这些配置/插件和目录联接点，并在便携 Data/config 中拒绝全局 config.json、自定义代理、命令、技能、工具与插件目录；扫描跳过 OpenCode 自动生成的 node_modules 依赖子树；扫描条目数限制为 50 万。因此复杂或大规模项目可能不能直接启动。这个扫描不是进程级沙箱，也无法保证 Web 中切换到其他目录时仍受约束。只在受控 Workspace 放可信项目，并在 Web 中只打开可信目录。文件编辑和 Shell 命令如何处理取决于所选审批档位；逐项审批档和工作区自动编辑档访问外部目录时请求确认，只读档拒绝。用户批准的命令可以运行项目代码并读取进程环境。

本地 Web 服务未设置 OPENCODE_SERVER_PASSWORD；绑定 127.0.0.1 仅阻止远程直连，不能隔离同机用户或进程对 API 的访问。离开共用电脑前停止服务，并将该电脑和 U 盘视为可接触明文 Key 的环境。测试脚本的日志脱敏结论只覆盖隔离启动器日志；本次另抽查一份本机 OpenCode 日志未包含假 Key，不能保证所有插件、项目命令或系统日志均不记录敏感信息。

## 跨电脑 Web 服务记录恢复（2026-10-03）

U 盘的 10 月 2 日启动日志出现 PCA201/PCA202：服务记录仍指向另一盘符的程序，退出入口也因路径不符拒绝清理。新版在启动及退出时持有同一启动器锁，先核实记录的进程编号、UTC 启动时间和原程序路径。进程不存在、编号已被新进程复用或实际程序路径不符时，将旧 JSON 原样移动到 Data/run/web-server.stale-时间-随机值.json。备份失败报 PCA204，保留原记录；无法核实进程报 PCA202，损坏记录报 PCA201。仍在运行的另一套程序不会被清理或终止。

隔离测试使用真实启动器和假 Key：旧版在盘符变化、进程编号复用两项测试中失败；修复后两项通过，同时验证另一程序的有效记录与损坏 JSON 均保持原样。未据此确认学校浏览器中的未知错误已解决；目标机真实对话仍需重试。
